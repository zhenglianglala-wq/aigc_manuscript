# Photo API v1 — separate from video

Independent photo projects. `/api/photo-projects` never requires a video project. Errors use existing `{error:{code,message,retryable}}`. Image credentials and approval are separate from video/text credentials. No external calls in fixture mode.

## Project and structured prompt
POST `/api/photo-projects` `{title?:string,brief:{description:string,style:"写实摄影",aspect_ratio:"1:1"|"3:2"|"2:3",must_include:[],must_avoid:[]}}` →201 PhotoProject `{id,title,brief,current_revision:1,prompt:null,created_at,updated_at}`. GET collection →array; GET by id →object; DELETE cascades photo data/assets/tasks (existing backups independent).
PATCH `/api/photo-projects/{id}` `{base_revision:N,title?:string,brief?:PhotoBrief}`. Changing brief clears prompt to avoid stale facts.
Structured PhotoPrompt `{subject,environment,composition,lighting,color,mood,details,negative_constraints:[],compiled_prompt,confirmed:false,generation_mode:"fixture"|"openai-compatible"}`. All fields strings except negative array, confirmed flag. Compiler derives positive prompt from six fields plus details; negative terms remain metadata.
POST `/api/photo-projects/{id}/prompt-runs` `{base_revision:N,idempotency_key:"...",instruction:"",approval_id:null}` →202 Run. Run contains `project_id:null,photo_project_id:ID,kind:"photo_prompt",status,base_revision,mode,steps,usage,result,error,proposal_id` and normal id. Poll existing GET `/api/runs/{id}`, cancel existing POST `/cancel`. New prompt is a candidate, never silently replaces current.
GET `/api/photo-projects/{id}/proposals` →array `{id,photo_project_id,base_revision,status:"pending",prompt,diff,created_at,run_id}`. POST `/api/photo-proposals/{id}/apply` `{base_revision:N}` →PhotoProject. POST `/dismiss` →Proposal.
PATCH `/api/photo-projects/{id}/prompt` `{base_revision:N,changes:{subject?,environment?,composition?,lighting?,color?,mood?,details?,negative_constraints?}}` →PhotoProject; recompile atomically, reset confirmed=false. POST `/prompt/confirm` `{base_revision:N}` →PhotoProject new revision confirmed=true.
GET `/api/photo-projects/{id}/revisions` →array `{version,parent_version,prompt,brief,title,source,created_at}`. POST `/revisions/{version}/restore` `{base_revision:N}` →PhotoProject new revision; restored prompt requires reconfirmation.
GET `/api/photo-projects/{id}/exports?format=json|markdown` →attachment of current prompt. Missing prompt gives409.

## Image generation (separate explicit button)
POST `/api/photo-projects/{id}/image-runs` `{base_revision:N,idempotency_key:"...",approval_id:null}` →202 Run `{kind:"photo_image",...}`. Only current confirmed prompt allowed. It captures prompt version + compiled text + image settings. Each run exactly one image, no automatic retry. Idempotent requests return same task; changing prompt/settings with same key conflicts.
Succeeded image run `result:{asset_id:ID}`. GET `/api/photo-projects/{id}/assets` →array Asset `{id,photo_project_id,prompt_revision,prompt_text,mode:"fixture"|"openai-compatible",label,size,model,settings_snapshot,mime_type,width,height,created_at,preview_url:"/api/photo-assets/ID/preview",download_url:"/api/photo-assets/ID/download"}`. Existing assets do not change when prompt edited.
GET `/api/photo-assets/{id}/preview` and `/download` serve local validated bytes; download attachment. Fixture is a visibly labelled "离线占位图，非 AI 照片" SVG, not represented as model output. Real provider: `/images/generations`, n=1, JSON response with `data[0].b64_json`. Generic auto/b64_json protocols only support Base64. URL-only generic responses fail clearly; explicit aliyun_url protocol follows the restricted official-result download rules below.

## Model settings and approval
GET/PATCH `/api/photo-settings/image` returns `{mode:"fixture"|"openai-compatible",base_url,model,size:"1024x1024"|"1536x1024"|"1024x1536",response_format:"auto"|"b64_json"|"aliyun_url",estimated_price_per_image:null,price_date:null,key_present:false,paid_calls_enabled:false,base64_only:true|false}`. `auto` omits response_format (for modern image models); b64_json explicitly requests it; aliyun_url selects the separately restricted Aliyun protocol below. Image Key env ONLY `IMAGE_API_KEY`; base_url/model/mode default from `IMAGE_BASE_URL/IMAGE_MODEL/IMAGE_MODE`; paid switch ONLY `PAID_IMAGE_CALLS_ENABLED`. Secret cannot be set or returned via API. Image settings independent from `/settings/model` text settings.
GET `/api/photo-settings/prompt` returns current text settings plus `approval_scope:"photo_prompt"` (read-only; text model config shared with existing LLM settings). Video approvals cannot authorize photo prompt or image calls.
GET `/api/photo-approvals?photo_project_id=ID` →array. POST `{photo_project_id:ID,purpose:"prompt"|"image",max_calls:1,accept_unknown_cost:true,budget:null,expires_in_minutes:60}` →Approval `{id,photo_project_id,purpose,status,calls_used,max_calls,budget,spent,expires_at,model_binding,created_at}`. Unknown price requires acceptance. Purpose/model/parameters bound; changing settings requires a new approval. DELETE `/api/photo-approvals/{id}` revokes. Fixture never consumes approvals.

Photo storage: entities `photo_project/photo_revision/photo_proposal/photo_asset/photo_approval`; their SQL project_id is null, explicit photo_project_id checked in photo API. Photo Run shares existing run kind with project_id:null and explicit photo_project_id. Backup must validate photo references too. Assets stored under data/photo-assets/{UUID}. No arbitrary file path is accepted.

Additions: PhotoPrompt also has editable `camera` and `style` strings, included in compilation. GET `/api/photo-projects/{id}/runs` returns project-filtered task history. Asset internal `filename` is `UUID.svg|png|jpg|webp`, relative to data/photo-assets; no arbitrary path.

## Direct supplied Prompt is an independent image entry
POST image-runs additionally accepts `direct_prompt?:string` (1–16000 characters, exact whitespace preserved) and `confirm_direct_prompt:boolean` (default false). When direct_prompt is present, confirm_direct_prompt must be true; backend checks brief hard constraints against that exact text, snapshots it without adding templates, and never calls a text model or changes PhotoProject.prompt/revision. Otherwise the existing confirmed-project-prompt path remains unchanged. Both paths require the same separate image-purpose authorization in real mode.
Asset adds `prompt_source:"direct"|"project"`, `source_project_revision:N`; direct assets have `prompt_revision:null` and exact supplied `prompt_text`. Project-source assets keep the confirmed prompt revision. Frontend distinguishes these labels explicitly.

## Aliyun Beijing URL protocol
`response_format` additionally accepts `aliyun_url`, bound into image approval settings; switching invalidates prior approvals. Only official Beijing `https://dashscope.aliyuncs.com/compatible-mode/v1` or `https://WORKSPACE.cn-beijing.maas.aliyuncs.com/compatible-mode/v1` endpoints. Request n=1, original Prompt, `prompt_extend:false`; response_format is omitted. Synchronous generation timeout 600 seconds, no automatic retry.
In this explicit protocol only, `data[0].url` downloads from HTTPS exact result hosts `dashscope-result-sz.oss-cn-shenzhen.aliyuncs.com` or `dashscope-result-bj.oss-cn-beijing.aliyuncs.com`. Credentials, fragments, non443 ports, redirects and nonglobal DNS addresses are rejected. The GET connects to the validated IP with official Host and TLS SNI, disables proxies, carries no API Key, and validates MIME, <=20MiB and actual Pillow decoding. Signed result URLs are not stored or exposed. Download is part of the approved one-image task. `base64_only:false` in this protocol; generic auto/b64_json remain Base64-only.
Official source: https://help.aliyun.com/zh/model-studio/qwen-image-generation-and-editing-api-reference . Fixed hostname list deliberately fails closed if provider returns a new result bucket.

## Dynamic official OSS hosts and download recovery
Aliyun FAQ documents dynamic result names. The allowed host pattern is `dashscope-{identifier}.oss-accelerate.aliyuncs.com` or `dashscope-{identifier}.oss-cn-{region}.aliyuncs.com`, with identifier/region restricted to bounded DNS-safe lowercase labels. Every other HTTPS/DNS/IP pinning/MIME/size/decode guard remains. Source: https://help.aliyun.com/zh/model-studio/qwen-image-api . This supersedes the fixed bucket list above.
Before any result download, server atomically stores a private receipt at `data/photo-receipts/{run_id}.json`, owner-only permissions, containing signed URL, request ID and original run/project IDs. It is never returned by any API, export or media backup. Public Run has only `image_receipt:{available:true,host,request_id}`; errors include safe hostname/stage, never URL query.
POST `/api/photo-projects/{id}/runs/{run_id}/recover-image` `{idempotency_key:"..."}` →202 recovery Run (`kind:"photo_image_recovery"`, `recovery_of:original_run_id`). Only failed/interrupted Aliyun image runs with private receipts qualify. The task makes a guarded result GET only: zero generation requests, zero approval calls consumed, zero new generation fees (network transfer may have provider-specific costs). Original prompt/settings/version snapshot is preserved even after project edits or settings changes. Recovery Run usage is zero for generation with `cost_status:"recovery_no_generation"`; original supplier usage remains on original Run. An existing running/succeeded recovery is reused to prevent duplicate assets. Missing old receipts cannot recreate a discarded URL; expired URLs fail explicitly without regenerating.

Cancelled original image tasks and deleted projects reject recovery. Recovered assets retain `run_id` of original generation, plus optional `recovery_run_id`; delete photo project removes its private receipts.

## Inline confirmation config snapshot
POST photo-approvals accepts optional `expected_model_binding`, exactly the model binding displayed in the user's confirmation. Image: `{base_url,model,size,response_format,estimated_price_per_image}`; prompt: `{base_url,model,input_price_per_million,output_price_per_million,max_output_tokens}`. The approval transaction compares the current configuration; differences return409 APPROVAL_CONFIG_CHANGED without creating approval. Existing clients may omit this field; inline confirmation clients must send their displayed snapshot.

## Writing quality and result feedback (2026-10-15)

Photo prompt run accepts creative_direction: faithful (default), cinematic, commercial. This remains a separate text task requiring its own approval in real mode. Schema adds optional/defaulted creative_direction and assumptions (max16, each max600 characters); compilation never appends assumption notes to the positive Prompt. Candidates retain direction and diagnostic report. Old records remain readable.

POST /api/photo-projects/{id}/quality: {base_revision,text?:string,baseline?:string}, text/baseline 1–16000 characters. Checks the original saved prompt/brief if text omitted; checks supplied raw text otherwise. Returns version, current/baseline evidence and advice, no aesthetic score or winner. Version mismatch409. Local read-only computation, no model call or approval consumed.

POST /api/photo-assets/{id}/feedback: adherence/composition/lighting strict integers1–5, notes max2000 characters. Freezes asset ID, actual Prompt/model/settings/source revision and asset_mode, marked user-reported; not a model-quality assertion. GET /api/photo-projects/{id}/feedback lists project records. Included in SQLite backups; project deletion removes feedback. This does not generate images or automatically update prompts.
