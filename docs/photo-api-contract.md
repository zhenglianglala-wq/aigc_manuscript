# Photo API v1 — separate from video

Independent photo projects. `/api/photo-projects` never requires a video project. Errors use existing `{error:{code,message,retryable}}`. Image credentials and approval are separate from video/text credentials. No external calls in fixture mode.

## Project and structured prompt
POST `/api/photo-projects` `{title?:string,brief:{description:string,style:"写实摄影",aspect_ratio:"1:1"|"3:2"|"2:3",must_include:[],must_avoid:[]}}` →201 PhotoProject `{id,title,brief,current_revision:1,prompt:null,created_at,updated_at}`. GET collection →array; GET by id →object; DELETE cascades photo data/assets/tasks (existing backups independent).
PATCH `/api/photo-projects/{id}` `{base_revision:N,title?:string,brief?:PhotoBrief}`. Changing brief clears prompt to avoid stale facts.
Structured PhotoPrompt `{subject,environment,composition,lighting,color,mood,details,negative_constraints:[],compiled_prompt,confirmed:false,generation_mode:"fixture"|"openai-compatible"}`. All fields strings except negative array, confirmed flag. Compiler derives positive prompt from six fields plus details; negative terms remain metadata.
POST `/api/photo-projects/{id}/prompt-runs` `{base_revision:N,idempotency_key:"...",instruction:"",approval_id:null}` →202 Run. Run contains `project_id:null,photo_project_id:ID,kind:"photo_prompt",status,base_revision,mode,steps,usage,result,error,proposal_id` and normal id. Poll existing GET `/api/runs/{id}`, cancel existing POST `/cancel`. New prompt is a candidate, never silently replaces current.
GET `/api/photo-projects/{id}/proposals` →array `{id,photo_project_id,base_revision,status:"pending",prompt,diff,created_at,run_id}`. POST `/api/photo-proposals/{id}/apply` `{base_revision:N}` →PhotoProject. POST `/dismiss` →Proposal.
PATCH `/api/photo-projects/{id}/prompt` `{base_revision:N,changes:{subject?,environment?,composition?,lighting?,color?,mood?,details?,negative_constraints?}}` →PhotoProject; recompile atomically, reset confirmed=false. POST `/prompt/confirm` `{base_revision:N}` →PhotoProject new revision confirmed=true.
GET `/api/photo-projects/{id}/revisions` →array `{version,parent_version,prompt,brief,title,source,created_at}`. POST `/revisions/{version}/restore` `{base_revision:N}` →PhotoProject new revision; restored prompt requires reconfirmation.
GET `/api/photo-projects/{id}/exports?format=json|markdown` →attachment of current prompt. Missing prompt gives409.

## Image generation (separate explicit button)
POST `/api/photo-projects/{id}/image-runs` `{base_revision:N,idempotency_key:"...",approval_id:null}` →202 Run `{kind:"photo_image",...}`. Only current confirmed prompt allowed. It captures prompt version + compiled text + image settings. Each run exactly one image, no automatic retry. Idempotent requests return same task; changing prompt/settings with same key conflicts.
Succeeded image run `result:{asset_id:ID}`. GET `/api/photo-projects/{id}/assets` →array Asset `{id,photo_project_id,prompt_revision,prompt_text,mode:"fixture"|"openai-compatible",label,size,model,settings_snapshot,mime_type,width,height,created_at,preview_url:"/api/photo-assets/ID/preview",download_url:"/api/photo-assets/ID/download"}`. Existing assets do not change when prompt edited.
GET `/api/photo-assets/{id}/preview` and `/download` serve local validated bytes; download attachment. Fixture is a visibly labelled "离线占位图，非 AI 照片" SVG, not represented as model output. Real provider: `/images/generations`, n=1, JSON response with `data[0].b64_json`. First release ONLY supports Base64 return. URL-only response fails clearly; no automatic remote URL download.

## Model settings and approval
GET/PATCH `/api/photo-settings/image` returns `{mode:"fixture"|"openai-compatible",base_url,model,size:"1024x1024"|"1536x1024"|"1024x1536",response_format:"auto"|"b64_json",estimated_price_per_image:null,price_date:null,key_present:false,paid_calls_enabled:false,base64_only:true}`. `auto` omits response_format (for modern image models); b64_json explicitly requests it. Image Key env ONLY `IMAGE_API_KEY`; base_url/model/mode default from `IMAGE_BASE_URL/IMAGE_MODEL/IMAGE_MODE`; paid switch ONLY `PAID_IMAGE_CALLS_ENABLED`. Secret cannot be set or returned via API. Image settings independent from `/settings/model` text settings.
GET `/api/photo-settings/prompt` returns current text settings plus `approval_scope:"photo_prompt"` (read-only; text model config shared with existing LLM settings). Video approvals cannot authorize photo prompt or image calls.
GET `/api/photo-approvals?photo_project_id=ID` →array. POST `{photo_project_id:ID,purpose:"prompt"|"image",max_calls:1,accept_unknown_cost:true,budget:null,expires_in_minutes:60}` →Approval `{id,photo_project_id,purpose,status,calls_used,max_calls,budget,spent,expires_at,model_binding,created_at}`. Unknown price requires acceptance. Purpose/model/parameters bound; changing settings requires a new approval. DELETE `/api/photo-approvals/{id}` revokes. Fixture never consumes approvals.

Photo storage: entities `photo_project/photo_revision/photo_proposal/photo_asset/photo_approval`; their SQL project_id is null, explicit photo_project_id checked in photo API. Photo Run shares existing run kind with project_id:null and explicit photo_project_id. Backup must validate photo references too. Assets stored under data/photo-assets/{UUID}. No arbitrary file path is accepted.

Additions: PhotoPrompt also has editable `camera` and `style` strings, included in compilation. GET `/api/photo-projects/{id}/runs` returns project-filtered task history. Asset internal `filename` is `UUID.svg|png|jpg|webp`, relative to data/photo-assets; no arbitrary path.

## Direct supplied Prompt is an independent image entry
POST image-runs additionally accepts `direct_prompt?:string` (1–16000 characters, exact whitespace preserved) and `confirm_direct_prompt:boolean` (default false). When direct_prompt is present, confirm_direct_prompt must be true; backend checks brief hard constraints against that exact text, snapshots it without adding templates, and never calls a text model or changes PhotoProject.prompt/revision. Otherwise the existing confirmed-project-prompt path remains unchanged. Both paths require the same separate image-purpose authorization in real mode.
Asset adds `prompt_source:"direct"|"project"`, `source_project_revision:N`; direct assets have `prompt_revision:null` and exact supplied `prompt_text`. Project-source assets keep the confirmed prompt revision. Frontend distinguishes these labels explicitly.
