# Prompt 差异化与验证方法

本项目的优势目标是稳定实现用户意图、连续性和可修改性。当前没有真实模型或视频对比结果，不能声称优于其他模型。

## 产品中实现的控制点

1. 先确认故事、人物与约束，再生成时间轴，减少单次自由扩写的漂移。
2. 逐秒内容负责编辑，分镜 Prompt 负责连续生成；不把 30 条逐秒描述机械拼成一条长指令。
3. 保留统一人物/场景 ID，局部重写锁定字段，检查时间和约束。
4. 模型输出经结构校验；用户看到候选差异，应用后才成为正式版本。
5. Prompt、源剧本、适配规则与反馈关联到版本，便于对照和回退。
6. 对话记忆需要确认，项目间隔离；本次明确要求优先于历史偏好。

## 适配与提示词调优

将提示词拆成独立的故事生成、时间轴、局部重写和对话模板。只调整有证据影响结果的环节，版本化保存。

通用文生视频规则保留主体、环境、动作、镜头和风格；动作优先的图生视频规则着重动作和镜头。规则配置不等于供应商效果验证。Runway 官方文档建议简洁、正向、具体动作，指出在一个短片段中堆叠多个逐秒切换可能导致意外结果：

https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide

把禁止内容保存在检查元数据中；仅在目标接口支持时输出负面 Prompt，不给所有模型套用同一种格式。

## 比其他模型写得更好的实验

阶段一：使用 evals/ 的固定 50 例，比较“同一个文本模型直接写 Prompt”与“本项目工作流”。相同简介、目标时长和视频模型；固定文本模型设置，记录所有调用与成本。离线 fixture 只能验证程序和结构。

阶段二：保留一批未用于调模板的输入作为留出集，避免只对 50 个训练样例优化。遮蔽 A/B 方法名称和顺序，让评审按需求遵循、故事完整、节奏、视觉可执行性、连续性和 Prompt 清晰评分。

阶段三：用户用同一个视频模型、相同画幅/时长/参考图生成 A/B；支持 seed 的模型使用配对 seed，并用多个 seed/重复生成。不支持 seed 时记录该限制。评分维度增加提示遵循、角色一致、动作自然、镜头一致和修正次数。保存视频链接、源版本与实际 Prompt。

分别报告结构通过率、盲评偏好率、每维分数、首次成功率、人工修改次数和费用。样例少时报告原始数量与不确定性，不给出“全面领先”。先定位失败类别，再改变一个模板或规则，回归后决定保留。

CLI `scripts/compare_prompts.py` 将两个已导出的 JSON 按分镜匿名打乱，生成盲评表；不调用任何模型。它不自动判定胜负。真实视频生成及真实模型评估均需用户批准费用。
