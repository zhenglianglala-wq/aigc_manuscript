# Prompt 差异化与验证方法

本项目的优势目标是稳定实现用户意图、连续性和可修改性。当前没有真实模型或视频对比结果，不能声称优于其他模型。

## 产品中实现的控制点

1. 先确认故事、人物与约束，再生成时间轴，减少单次自由扩写的漂移。
2. 逐秒内容负责编辑，分镜 Prompt 负责连续生成；不把 30 条逐秒描述机械拼成一条长指令。
3. 保留统一人物/场景 ID，局部重写锁定字段，检查时间和约束。
4. 模型输出经结构校验；用户看到候选差异，应用后才成为正式版本。
5. Prompt、源剧本、适配规则与反馈关联到版本，便于对照和回退。
6. 对话记忆需要确认，项目间隔离；本次明确要求优先于历史偏好。

## 适配与提示词调优

将提示词拆成独立的故事生成、时间轴、局部重写和对话模板。只调整有证据影响结果的环节，版本化保存。

通用文生视频规则保留主体、环境、动作、镜头和风格；动作优先的图生视频规则着重动作和镜头。规则配置不等于供应商效果验证。Runway 官方文档建议简洁、正向、具体动作，指出在一个短片段中堆叠多个逐秒切换可能导致意外结果：

https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide

把禁止内容保存在检查元数据中；仅在目标接口支持时输出负面 Prompt，不给所有模型套用同一种格式。

## 比其他模型写得更好的实验

阶段一：使用 evals/ 的固定 50 例，比较“同一个文本模型直接写 Prompt”与“本项目工作流”。相同简介、目标时长和视频模型；固定文本模型设置，记录所有调用与成本。离线 fixture 只能验证程序和结构。

阶段二：保留一批未用于调模板的输入作为留出集，避免只对 50 个训练样例优化。遮蔽 A/B 方法名称和顺序，让评审按需求遵循、故事完整、节奏、视觉可执行性、连续性和 Prompt 清晰评分。

阶段三：用户用同一个视频模型、相同画幅/时长/参考图生成 A/B；支持 seed 的模型使用配对 seed，并用多个 seed/重复生成。不支持 seed 时记录该限制。评分维度增加提示遵循、角色一致、动作自然、镜头一致和修正次数。保存视频链接、源版本与实际 Prompt。

分别报告结构通过率、盲评偏好率、每维分数、首次成功率、人工修改次数和费用。样例少时报告原始数量与不确定性，不给出“全面领先”。先定位失败类别，再改变一个模板或规则，回归后决定保留。

CLI `scripts/compare_prompts.py` 将两个已导出的 JSON 按分镜匿名打乱，生成盲评表；不调用任何模型。它不自动判定胜负。真实视频生成及真实模型评估均需用户批准费用。

## 2026-10-15：已实现的第二轮差异化

产品定位：把用户意图转成可执行的视觉方案，并且知道下一次应当改什么。单纯加长Prompt或换一个大模型容易复制；逐步积累“原始需求—实际Prompt—模型参数—生成结果—人工反馈”的可追溯记录，才有机会形成项目自己的优化依据。

| 层 | 已实现 | 具体作用 |
| --- | --- | --- |
| 创作控制 | 忠实还原 / 电影叙事 / 商业画面三种方向 | 在同一事实边界内改变构图、光线与视觉层级；方向和规则版本入任务快照 |
| 事实与补充分开 | assumptions列表、候选应用与确认 | 让用户知道哪些细节是补充选择，避免把“脑补”当原始要求；人工修改以后以当前字段为准 |
| 写作诊断 | 主体、构图、光线、色彩线索；抽象修饰、可能冲突、硬约束检查 | 每个问题有原文依据和改进建议，无美学总分，不自动改稿或收费 |
| 对照 | 粘贴另一个版本，并列显示写作线索 | 相同原始简介进行检查；不是自动选出获胜图片 |
| 视频完整性 | 动作优先适配1.1保留分镜中每秒动作及镜头变化 | 修复原先只保留首秒动作的问题；仍不承诺外部模型按秒执行 |
| 结果反馈 | 照片历史中的遵循/构图/光线1–5分及备注 | 人工反馈冻结图片的实际Prompt、源版本、模型和参数；不是模型自动裁判，离线占位图与真实图分别标记 |

操作入口：照片“Prompt编写”选择优化方向，生成候选、比较并应用；“Prompt诊断与对照”检查当前已保存内容或直接输入。照片历史展开“评价这张照片”保存并重读反馈。视频“检查与质量”增加可执行性建议。

写作原则参考：[Google Veo指南](https://deepmind.google/models/veo/prompt-guide/)的主体、动作、镜头与光线分解，以及[Runway视频指南](https://help.runwayml.com/hc/en-us/articles/39789879462419-Gen-4-Video-Prompting-Guide)的具体运动描述和渐进迭代。规则按用途区分，不把一套供应商建议当作所有模型的保证。

## 如何证明新Prompt更好

1. **先定目标**：故事短片看叙事与连续性；人物照片看身份、姿态和光线；产品画面看材质、主体占比与文案约束。每个案例保存不可改变的事实和允许补充的内容。
2. **基线公平**：A为同一个文本模型直接写Prompt，B为本项目工作流。用相同简介、目标生成模型、画幅、尺寸与文本设置；记录两组全部调用/耗时/费用，不能把多轮高成本工作流冒充相同成本优势。
3. **一次验证一个改动**：先测方向和事实保留，再测诊断引导修改。不要同时换文本模型、图像模型、Prompt模板和采样设置。
4. **生成后盲评**：隐藏A/B来源、随机展示顺序。评审先按不可改变事实判断是否合格，再评价构图、光线和叙事。当前照片接口未暴露seed，不假称已固定种子；获得费用批准后做多次重复，并报告随机性。
5. **区分成功率与偏好**：硬约束合格率、盲评偏好、首次可用率、平均修改次数、每个可用结果成本分别报告。展示原始人数/案例数，避免用少量精选案例给出胜率结论。
6. **留出集**：当前50固定案例用于回归；另留未参与改模板的真实需求，确认改进能泛化。先选择小批获批实验，再按效果扩展，不在后台自动批量生成。

建议首批实验覆盖人物、产品、场景、文字布局和连续动作，并由两位评审独立评价。照片对照盲评图片的组织与匿名化目前仍需人工进行；现有CLI仅支持视频分镜文字。反馈记录尚未自动汇总成训练集，也没有自动微调或跨项目记忆学习。下一阶段优先做可审计的盲评导出、失败类型统计，再评估是否需要经过用户确认的案例检索。

当前证据只支持功能与约束回归通过，不能证明新文字模型输出或实际视觉质量优于其他模型。离线方向模板仍明确标注为示例，真实扩写需要配置并批准文字调用。

升级说明：新增方向默认为忠实还原，旧文字任务按此默认值保持幂等。动作优先适配1.0的旧分镜可能提示Prompt待更新；旧版本不自动覆盖，编辑并保存逐秒内容或重新生成候选后，才使用1.1编译规则。
