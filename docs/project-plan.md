# AIGC 视频编剧工作台：完整项目计划书

版本：1.0 · 日期：2026-10-12 · 实施更新：2026-10-13。本文保留计划基线；当前实现与验收结果见 README.md 与 docs/validation.md。

## 1. 项目目标与已确定范围

构建本地单用户 Web 工作台，将用户的简短视频介绍扩写为故事、人物与场景设定、完整逐秒剧本和连续分镜生成 Prompt。通过项目内 Agent 对话讨论、修改与迭代，保存对话和用户确认的记忆，导出给用户选择的视频生成模型。

已确定：

- 通用短视频，优先故事短片。
- 本地单用户；前端使用 apple-interface-design 的设计方法。
- 逐秒剧本用于精细编辑，连续分镜 Prompt 用于主要生成导出。
- 用户在其他模型中生成视频；本项目不调用视频生成服务。
- 主 agent 统领，后端、前端、测试三个子 agent 分工协作。
- 目录遵循用户提供的 agents/tools/skills/workflows/prompts/context/memory/tests/evals 结构。
- 任何付费 API 调用、GPU 租用或付费部署须先获得用户批准。

第一版参数建议：时长 5–120 秒，默认 30 秒；简介 1–6000 字符；画幅支持 16:9、9:16、1:1。后续调整通过同一份 Schema、前端校验与边界测试同步完成。

第一版交付不包含多人账号系统、云部署、视频渲染、自动批量抓取视频网站或自动视频效果评分。网络参考采用可追溯公开来源，视频效果由用户回传并人工评价。

## 2. 使用流程与核心交付

### 2.1 创建与生成

1. 输入一句到一段简介，选择时长；其他设定提供默认值。
2. Agent 扩写故事，明确开头、发展、转折、结尾；缺失信息标记为创作补充。
3. 用户讨论或编辑故事，确认人物、场景及约束。
4. 生成分镜与逐秒剧本；每秒归属一个分镜，时间完整覆盖。
5. 展开某秒或某分镜，修改内容，或提出范围重写要求。
6. 检查结构、时间、引用、硬约束和连续性；展示具体问题与修正入口。
7. 导出 JSON、Markdown、CSV，或复制分镜 Prompt。
8. 可登记外部生成视频链接、实际模型、实际 Prompt 与人工评价，继续迭代。

### 2.2 对话辅助

项目内对话可以澄清需求、讨论剧情、解释 Prompt、引用故事/分镜/某秒并提出修改。普通聊天保存回复；涉及剧本修改时生成带差异的候选，用户应用后才改变正式版本。明确点击“生成”或“重写”授权生成对应范围候选，不授权覆盖其他内容。

不要求用户重复提供项目已确认的信息。每次调用使用哪些故事版本、消息和记忆可查看。对话与任务公开展示简明执行步骤、工具状态和结果，不存储或展示模型隐藏推理。

### 2.3 核心输出

- 扩写故事与创作假设。
- 人物/场景固定设定、视觉风格、硬约束。
- 分镜列表和每个分镜的连续生成 Prompt。
- 每秒画面、动作、镜头、对白/旁白、声音、Prompt 与连续性说明。
- 可选英文 Prompt；中文剧本默认保留。
- 检查结果、版本历史、任务与用量记录。
- 对话历史、记忆来源和可应用的修改候选。

逐秒时序是创作要求，导出不承诺外部模型准确执行每一秒。模型支持项、时长和 Prompt 格式由版本化适配配置表达；未知能力标记为未验证。负面约束仅在目标模型支持时单独输出。

## 3. 输入、输出与模块边界

| 类别 | 契约 |
| --- | --- |
| 必填输入 | 简介、目标时长；后端为最终校验来源 |
| 可选输入 | 风格、画幅、语言、受众、角色设定、必须/禁止内容、参考资料 |
| 对话输入 | 内容、项目/会话 ID、可选引用、客户端幂等键 |
| 修改输入 | 基础版本、目标秒/分镜范围、修改要求、锁定字段 |
| 正式输出 | Schema 校验通过的故事/时间轴/分镜/Prompt 及版本 |
| 候选输出 | 标明基础版本、变化范围、差异和问题，尚未应用 |
| 外部视频反馈 | 用户提供链接、生成模型、实际 Prompt 与评价；不冒充系统实测 |
| 错误输出 | 稳定错误码、可读说明、可重试状态、任务 ID；不返回密钥 |

前端只负责输入、展示、草稿和用户操作。后端负责模型访问、密钥、校验、持久化、流程与导出。Agent 通过受控工具工作，不能越过版本校验直接改库。网页、附件、参考 Prompt 是资料，不作为系统指令；资料来源与用户要求分开保存。

时间采用半开区间 `[start, end)`：N 秒必须覆盖 `[0,N)`，无空洞或重叠。每条逐秒项长度为 1 秒，分镜由连续秒聚合。修改某秒后，对应分镜 Prompt 标记为待更新，更新成功后才视为一致；导出要求一致或明确显示待更新问题。

## 4. 页面与交互设计

### 4.1 工作台

- 左侧：项目列表、创建入口、任务状态。
- 中间：故事 / 分镜 / 检查三个主视图；分镜页包含时间码和可展开的逐秒编辑。
- 右侧：编辑 / 对话面板，显示当前引用范围、局部重写、连续 Prompt。
- 工具栏：保存状态、版本、检查、导出。
- 设置：本地用户档案、默认偏好、模型配置、费用授权和数据管理。
- 记忆面板：待确认与已确认记忆、来源、作用范围、编辑、停用、删除。
- 运行记录：简明步骤、错误、耗时、Token、估算费用和价格依据。

### 4.2 Apple 风格落实

用文字层级、留白和对齐突出故事与编辑任务；玻璃主要用于导航和工具栏，正文保持稳定实色。提供常驻标签、明确焦点、错误修正说明和可恢复状态。窄窗口将辅助面板切为独立视图，并保留返回编辑位置。

支持键盘操作、200% 缩放、减少动态效果、减少透明度和不支持 blur 的实色降级。普通详情面板不困焦，确认对话框负责困焦及回焦。主题分别配置文字和材质，不能仅凭颜色表达错误或任务状态。

### 4.3 数据与异步状态

读请求使用取消机制和请求序号；快速切项目不能被迟到响应覆盖。写入携带基础版本；版本冲突保留草稿并提示比较。切换项目后回复仍归属原项目。未保存修改离开时提供保存或放弃。错误和刷新不静默清空输入。

## 5. 用户、对话与记忆设计

### 5.1 本地用户

初始化一个稳定 `owner_id`，保存显示名称、语言、默认时长/画幅/风格。第一版不增加登录页。项目、会话和记忆均记录归属，后端查询按归属与项目过滤。这里的 owner 是数据组织边界，不构成多人认证；多人模式需要另行实现身份认证和授权。

服务默认绑定 `127.0.0.1`，开发跨域仅允许明确前端地址。API Key 不进入浏览器存储或前端构建产物。

### 5.2 三类信息

| 类型 | 内容与规则 |
| --- | --- |
| 对话历史 | 保存原始用户、Agent、工具消息，按项目和会话归属，可检索、导出、清空 |
| 短期上下文 | 当前版本、近期消息、来源可追溯的摘要、本轮引用；按 Token 预算裁剪 |
| 长期记忆 | 用户确认的偏好、工作方式；项目记忆只在本项目，用户级偏好可跨项目 |

已确认的故事设定属于版本化项目数据，不依赖对话摘要恢复。长期记忆先产生候选，用户确认范围和内容后生效；模型推测、网页指令或一次性细节不能自动进入长期记忆。

### 5.3 记忆生命周期

`candidate → confirmed → inactive / deleted`；编辑增加版本。每条记忆保存来源消息或项目版本、作用范围、创建/更新时间和状态。

用户可以查看本轮使用的记忆，移除引用，修改、停用或删除。用户明确提出“不再记住”时，删除规则具有优先级；新任务不得通过历史消息重新提取同一失效记忆。必要的来源级排除标记仅用于防止复用，不保留已删除记忆正文。

删除消息后，依赖该消息的摘要和记忆候选失效并重建。删除记忆不自动删除原对话，界面明确提供分别管理的入口。清空项目或对话会处理关联缓存与摘要；旧上下文只保留审计引用，不继续注入。备份副本的删除与保留单独说明。

### 5.4 上下文组装顺序

系统/角色规则 → 当前用户请求与明确约束 → 当前已确认项目版本 → 用户确认的有效记忆 → 用户选定参考 → 近期消息与来源摘要。

冲突时优先采用当前明确用户要求，提示冲突；不能偷偷覆盖旧设定。超过预算时优先减少参考和历史消息，保留硬约束与来源。模型生成摘要也属于调用，遵守同一授权和用量规则；离线模式采用明确标注的可重复示例。

第一版使用 SQLite 结构化查询与 FTS5（运行环境不支持时退回普通查询）；只有跨项目语义检索存在实际需求时才评估向量库。

## 6. Agent 角色与执行流程

### 6.1 产品内角色

| 角色 | 职责 | 边界 |
| --- | --- | --- |
| 对话协调者 | 澄清需求、选择流程、提出修改与记忆候选 | 不直接写正式剧本 |
| 编剧 | 故事扩写、结构与情节 | 尊重用户约束与事实来源 |
| 分镜导演 | 分镜、逐秒画面、动作与镜头 | 时间覆盖和引用必须有效 |
| Prompt 编译器 | 将分镜编译为生成 Prompt、模型格式适配 | 不擅自改变故事事实 |
| 连续性审查者 | 人物、道具、场景、时间与约束检查 | 提供问题和依据，不自动覆盖 |

这些角色第一版是有明确输入输出的工作流步骤，不要求部署独立进程，也不引入额外多 Agent 框架。并行仅用于互相独立的处理；故事确认、时间轴生成和版本写入保持依赖顺序。

### 6.2 工作流

生成：校验输入 → 加载上下文 → 扩写 → 用户确认 → 生成时间轴 → 编译分镜 Prompt → 结构/约束检查 → 保存候选 → 应用为版本。

对话：校验消息 → 保存用户消息 → 组装上下文 → 生成回复/候选 → 校验 → 保存；用户应用候选另走版本写入事务。

重写：冻结基础版本与范围 → 保留锁定字段 → 生成候选 → 检查范围和邻镜衔接 → 比较 → 应用。

任务状态：`queued → running → validating → succeeded / failed / cancelled`。任务生成成功不等于候选已应用。失败保留已完成输出；取消后迟到结果不得自动提交。服务重启将未完成任务标记为 interrupted，允许用户选择重试，不自动产生新的付费调用。

模型结构输出修复最多一次；可恢复网络错误最多两次退避重试。鉴权、无额度、授权失效、预算不足直接停止。禁止无限修复和循环调用。

## 7. 技术方案与目录

前端：React + TypeScript + Vite。后端：Python + FastAPI + Pydantic。存储：SQLite，标准迁移机制。API：REST，任务进度优先轮询；聊天可在后续阶段添加 SSE，正确性不依赖流式展示。

使用通用文本模型适配器与明确标注的离线 fixture。真实适配器按经核验的服务协议接入，不声称兼容所有厂商。版本在实施时选择相互兼容的稳定版本并锁定。

## 8. 数据模型与版本

| 对象 | 主要字段 |
| --- | --- |
| UserProfile | owner_id、名称、语言、默认参数 |
| Project / Brief | owner_id、简介、参数、约束、当前版本、时间 |
| StoryBible | 故事、创作假设、角色/场景引用、确认状态 |
| SecondBeat | [start,end)、画面、动作、镜头、对白、声音、Prompt、角色/场景 ID |
| Shot | 时间范围、逐秒引用、连续 Prompt、衔接、适配配置版本 |
| Revision | 项目、版本、父版本、变更范围、来源、时间 |
| Conversation / Message | 归属、项目、角色、内容、引用、任务、幂等键 |
| ContextSnapshot / Summary | 使用的版本、来源消息、记忆引用、摘要版本和时间 |
| MemoryItem | owner_id、scope、project_id、source_ids、状态、版本 |
| ChangeProposal | base_revision、范围、差异、来源消息、状态 |
| Run / RunStep | 输入快照引用、阶段、模型/Prompt 版本、状态、Token、耗时、尝试、错误 |
| PriceConfig / Approval | 厂商/模型、价格单位及日期；批准范围、预算、有效期、撤销状态 |
| Reference / Feedback | 来源 URL、记录日期、模型、Prompt 关联、人工观察和评价 |

写入使用 SQLite 事务与乐观版本检查。恢复旧版创建新版本，不覆盖历史。普通聊天只写会话、消息和候选；正式产物必须经过应用流程。重复请求通过幂等键去重，取消不将上游已消耗费用记为零。

## 9. API 规划

统一 `/api` 前缀；成功响应携带对象及版本，错误响应包含 code/message/retryable/run_id（适用时）。无效输入返回 422，版本冲突返回 409，未授权模型调用返回明确业务错误。

| API | 用途 |
| --- | --- |
| GET /health | 本地服务状态 |
| GET/PATCH /api/profile | 用户档案及默认偏好 |
| GET/POST /api/projects | 列表与创建 |
| GET/PATCH/DELETE /api/projects/{id} | 查询、更新和明确删除项目 |
| POST /api/projects/{id}/runs | 指定扩写/时间轴/重写/检查任务 |
| GET /api/runs/{id} | 进度、输出引用、用量与错误 |
| POST /api/runs/{id}/cancel | 请求取消 |
| POST /api/projects/{id}/story/confirm | 确认故事版本 |
| PATCH /api/projects/{id}/beats/{second} | 人工编辑并创建版本 |
| GET /api/projects/{id}/revisions | 版本历史 |
| POST /api/projects/{id}/revisions/{version}/restore | 恢复为新版本 |
| GET /api/projects/{id}/exports?format=… | JSON / Markdown / CSV |
| GET/POST /api/projects/{id}/conversations | 项目会话 |
| GET/POST /api/conversations/{id}/messages | 消息与回复任务 |
| DELETE /api/conversations/{id} | 清空会话与依赖上下文 |
| DELETE /api/messages/{id} | 删除消息并使依赖摘要失效 |
| GET/POST /api/memories | 按作用范围查询和创建候选 |
| PATCH/DELETE /api/memories/{id} | 编辑、停用和删除 |
| POST /api/memories/{id}/confirm | 确认范围与版本 |
| GET /api/projects/{id}/proposals | 修改候选 |
| POST /api/proposals/{id}/apply 或 dismiss | 应用或放弃 |
| GET /api/runs/{id}/context | 查看本轮上下文来源 |
| GET/PATCH /api/settings/model | 模型配置状态和非敏感参数 |
| GET/POST/DELETE /api/approvals | 查询、创建及撤销用户批准记录 |
| POST /api/backups | 本地备份，不包含密钥 |

模型配置接口只返回密钥是否存在，不回显密钥。备份恢复通过本地脚本先验证到临时数据库，再经明确操作替换；不接受任意网络地址或路径作为恢复入口。

## 10. 环境、依赖与 Git

README 交付环境版本、安装、启动、测试、常见问题、离线/真实模式、备份和恢复。提供一个入口启动前后端，支持分别调试。依赖使用项目虚拟环境和锁文件，不修改系统 Python。

新增依赖必须说明用途、许可证与替代方案；只为具体需求添加。第一版不引入向量数据库、消息队列或重型 Agent 框架。核心时间覆盖、版本、授权等规则应可独立测试。

`.env.example` 保存变量名称、用途、默认示例和假值；不保存真实 API Key。`.env` 初始用空值赋值，例如：

```dotenv
LLM_API_KEY=
LLM_BASE_URL=
LLM_MODEL=
LLM_MODE=
DATA_DIR=
PAID_CALLS_ENABLED=
```

空值让凭证和付费访问默认不可用，便于复制配置并避免误调用。仅写裸变量名不能作为通用 dotenv 模板；采用 `NAME=`。实际配置可由本机 .env 或系统环境注入；程序提供非敏感默认值并校验必需项。

## 11. 费用批准与运行观察

默认离线 fixture，不消耗外部文本/视频额度。离线输出明确标记为示例，不声称真实模型生成。

真实调用前展示服务、模型、发送的数据范围、任务范围、调用上限、预算与估算依据。用户可以批准一次任务或有明确范围/预算/有效期的会话；相同范围内不重复打断，超出范围必须重新批准。撤销后不再发起新调用。配置 Key 或开启开关本身不等于批准。

若价格或 Token 不能确定，显示未知，用户仍需明确接受未知费用及调用次数上限；不能承诺硬性金额上限。已知价格时先估算、检查预算，再调用，并记录实际 usage；本地预算是控制机制，不能代替供应商账单。

记录每次尝试的模型、Prompt 版本、耗时、Token、重试、状态、费用来源及价格日期。分别统计首次成功率、重试后成功率、结构通过率与人工质量分。取消可能发生在供应商已计费之后，记录真实已知用量与未知项。日志脱敏，不写 Authorization、Key 或不必要的完整对话。

## 13. 测试与质量评估

### 13.1 tests：程序正确性

- unit：时间覆盖、分镜聚合、约束、上下文裁剪、记忆过滤、费用、导出。
- api：输入校验、项目持久化、版本冲突、任务终态、取消/重试、授权和错误恢复。
- e2e：真实前后端和 SQLite；模型部分用明确标记的 fixture，收费真实模型另行批准。

关键验收包括刷新恢复、导出解析、范围重写锁定字段、取消迟到结果、重复提交幂等、重启恢复、旧候选拒绝覆盖，以及跨项目数据不串用。

记忆专项：候选确认前不注入；用户级/项目级边界正确；来源可定位；编辑后采用最新有效版本；删除后原文不从摘要、缓存或历史提取重新进入上下文。备份恢复先在临时实例验证全部引用，损坏备份不得部分覆盖。

GUI 实际操作：创建 → 扩写 → 确认 → 时间轴 → 编辑 → 保存 → 刷新 → 导出；对话 → 修改候选 → 应用；记忆 → 确认 → 修改/删除 → 新对话。连续切换至少 20 次，加载中换项目、双标签冲突、离线/错误恢复、键盘、200% 缩放、窄视口和降级材质均需检查。

### 13.2 evals：输出质量

50 固定案例分布：故事短片 15，其他短视频 10，时长与节奏 5，连续性和硬约束 8，输入边界 7，编辑重写 5。另增加对话/记忆行为的程序回归，不挤占这 50 个创作案例。

机械检查：Schema、完整时间覆盖、分镜一致、ID 引用有效、字段完整、锁定约束和版本正确。有效输入必须通过机械校验；无效输入必须按契约明确拒绝。

人工量表 1–5 分：需求遵循、故事完整、节奏、视觉可执行性、连续性、Prompt 清晰度。事实型内容另列来源和未知项；创作补充明确标记。真实模型质量目标暂定关键维度均分 ≥4，任何硬约束失败必须修复；未运行真实模型时此门标记未验证。

摘要另抽查准确性、遗漏、冲突和偏好归纳。离线结构测试、真实模型质量、用户回传视频效果三类结果分别记录。

报告使用 passed/failed/blocked/skipped，绑定源码版本、运行环境、模型/模板、输入和证据。build 通过不能代表 GUI 通过，fixture 通过不能代表真实模型效果通过。

## 14. 开发团队与实施阶段

主 agent 负责统一契约、文档、环境/Git、风险判断、集成与交付。三个子 agent 负责后端、前端和独立测试；写码与验收分离。并发上限为主 agent 加三个子 agent。共享文件和契约变化先由主 agent 协调，避免同时覆盖。具体见 agent-team.md。

| 阶段 | 交付物 | 退出条件 |
| --- | --- | --- |
| P0 契约与环境 | 输入输出 Schema、API 文档、目录、README、agent.md、.env 模板、本地 Git | 分工和接口一致；密钥/数据忽略规则有效 |
| P1 持久化骨架 | 后端、数据库迁移、用户档案、项目与版本 API；前端基础布局 | 创建/编辑/刷新可重读；版本冲突测试通过 |
| P2 创作闭环 | 离线适配器、故事确认、分镜/逐秒编辑、Prompt 编译、检查与导出 | 离线完整流程真实 GUI 跑通，导出与来源版本一致 |
| P3 对话与记忆 | 会话、引用、上下文、修改候选、记忆确认/编辑/删除 | 聊天不自动改正式产物；项目隔离和删除失效通过 |
| P4 模型与成本 | 可配置真实文本适配器、批准记录、预算、任务日志、有限重试 | 未批准调用被拦截；授权测试仅在批准后执行 |
| P5 评估与交付 | 50 固定案例、独立审查、GUI 回归、备份恢复、最终说明 | 程序验收通过；真实模型未测项明确；没有阻断缺陷 |

依赖关系：P0 → P1 → P2；P1 完成后可并行准备 P3 数据层和前端对话组件；P4 配置与成本设计可提前，但付费运行保持审批门；P5 测试设计从 P0 开始，最终验收在集成之后。排期按各阶段实际结果更新，不凭未实现代码承诺固定交付时间。

## 15. 风险与对应设计

| 风险 | 处理 |
| --- | --- |
| 每秒动作过密、叙事割裂 | 同时保留连续分镜，检查动作负载和衔接 |
| 人物/道具漂移 | 固定设定、引用 ID、锁定字段、范围重写后检查 |
| 模型 JSON 错误 | Schema 校验、有限修复、错误可恢复 |
| 旧结果覆盖新编辑 | base_revision、幂等键、候选应用、取消迟到保护 |
| 记忆串项目或保留错误 | 默认项目隔离、明确确认、来源追溯、失效传播 |
| 费用不可知或重试膨胀 | 调用审批、次数/Token 上限、价格依据、未知项明示 |
| 未配置模型却展示虚假成功 | fixture 标签、真实配置状态、独立报告 |
| 本地数据丢失 | 数据库事务、迁移、备份与验证后恢复 |
| 外部代码和依赖失控 | 许可证核验、小范围复用、锁文件 |

## 17. 照片模块扩展

新增独立照片工作区，提供两个可分别使用的功能：简介扩写为可编辑、可确认的照片 Prompt；使用确认过的项目 Prompt 或直接粘贴已有 Prompt 生成图片。直接输入路径不调用文字模型、不改变结构化 Prompt。图片结果保留实际文字、来源、版本和参数。

图片服务接入 OpenAI 图片接口兼容服务，使用独立密钥、费用开关及用途批准；默认仅生成明确标注的离线占位图。接收 Base64 PNG/JPEG/WebP，限制响应大小并实际解码验证。包含照片的备份同时保存数据库和图片文件。边界及验收见 docs/photo-module.md、docs/photo-api-contract.md 和 docs/photo-validation.md。
